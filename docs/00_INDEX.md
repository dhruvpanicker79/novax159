## Documentation rules for this project

Six people writing code in five days with AI assistance produces drift fast. These rules are cheap and they stop it.

1. **Every non-obvious decision goes in `04_DECISIONS.md`** as a numbered ADR, with the alternatives we rejected and the reason. If someone later asks "why dpkt and not scapy?", the answer must already be written down.
2. **Every work session appends to `05_WORKLOG.md`** — date, who, what changed, what broke, what's next. This becomes the source material for the final report and the PPT's progress slide.
3. **The schema is the contract.** `03_ARCHITECTURE.md` defines it. If you change a field, you change the doc in the same commit, and you tell the team. No silent schema edits.
4. **Findings carry their citations.** Every detection rule names the RFC/NIST clause it enforces. This is a scored PS requirement, not decoration — and it is far cheaper to write at the moment you author the rule than to backfill on day 4.
5. **Docs live in git alongside the code.** No Google Docs, no WhatsApp as a spec.
6. **One source of truth per fact.** If it's in the architecture doc, don't restate it in the USP doc — link to it.
